CLI의 `--project`로 지정된 격리 프로젝트에서, 새 씬 `Assets/Scenes/Mario1A.unity`에 마리오풍 2.5D 조작 레이어를 제작해줘. 이번 단계는 레벨이 아니라 **조작만** 만든다.

[격리 및 오염 방지 — 최우선]
- 이 요청의 유일한 최종 씬 경로는 `Assets/Scenes/Mario1A.unity`다. 다른 씬 경로를 만들거나 사용하지 마라.
- 작업 시작 전에 위 대상 씬이 이미 존재하는지 확인하라. 존재한다면 Unity를 변경·저장·삭제하지 말고 `isolated_target_already_exists`를 보고한 뒤 중단하라.
- 대상이 없을 때에만 위 경로에 새 Basic Scene을 정확히 한 번 만들고, 그 씬만 열어 작업하라.
- `Assets/Scenes`의 다른 모든 씬은 열거나 변경·저장·삭제하지 마라. 어떤 파일도 삭제하지 마라.
- 이 실행에서 생성한 대상 씬은 검증 실패 시 재생성·초기화하지 말고 실패한 항목만 수정한 뒤 재검증하라.
- 씬 외에는 `Assets/Scripts/MarioMovement.cs`, `Assets/Scripts/SideScrollerCamera.cs`만 생성·수정할 수 있다. 그 밖의 기존 에셋과 스크립트는 변경하지 마라.
- 두 스크립트가 이미 있으면 **먼저 읽고** 중복 클래스를 만들지 말며, 필요한 부분만 고쳐라.

[중요]
이 요청은 제작, Play Mode 실측 검증, 실패 수정, 재검증까지 포함한다.
모델의 설명만으로 완료하지 말고 모든 합격 조건을 실제 Unity 도구 결과로 확인해라.
검증 실패 시 기존 산출물을 재생성하지 말고 실패 항목만 수정한 뒤 다시 검증해라.
최종 완료 판정은 호스트 검증에 맡겨라.

[씬 구성 — 최소]
- 3D Rigidbody와 Collider를 사용하는 2.5D 횡스크롤
- Ground: 위치 (19, -0.5, 0), 크기 (44, 1, 4) 큐브 하나. 이것 말고 다른 지형을 만들지 마라
- Player: 위치 (0, 1, 0)
- **시작 위치 좌우 각 8유닛에는 어떤 수직 장애물도 없어야 한다.** 이 단계에서는 아예 아무것도 두지 마라
- Main Camera는 Player를 부드럽게 추종하되 Z는 고정하고, 플레이어와 8유닛 이상 떨어져 스테이지가 보이게 한다
- 씬을 반드시 저장

[Player 필수 구성]
- 이름: Player
- Rigidbody
- Collider
- MarioMovement
- MeshRenderer (화면에 보여야 한다)
- **Rigidbody.constraints는 정수 120이다** (FreezePositionZ | FreezeRotationX | FreezeRotationY | FreezeRotationZ). 씬 값과 스크립트 대입 **양쪽 모두** 이 값이어야 한다
- 낙사 시 시작 위치로 복귀

[카메라 필수 구성]
- 이름: Main Camera
- Camera
- SideScrollerCamera
- Player의 X/Y를 추종하되 Z는 고정
- 플레이 시작 직후 target이 null이 아니어야 함
- 카메라 Z 오프셋을 매 프레임 누적하지 마라. 시작 Z를 기억해 그 값을 유지한다

[조작]
- A 또는 Left Arrow: 왼쪽 이동
- D 또는 Right Arrow: 오른쪽 이동
- Space: 점프
- 이동 방향이 존재하는 동안 Left Shift 또는 Right Shift를 누르면 그 방향으로 대시
- 대시 지속시간 0.3초
- 대시 재사용 대기시간 0.6초
- 대시 속도는 일반 이동 속도의 2배
- 대시 중에도 Y 속도는 보존

[입력 구현]
- New Input System의 Keyboard.current만 사용
- legacy UnityEngine.Input API 사용 금지
- Rigidbody.linearVelocity 사용
- 키보드 null 체크
- 바닥에 있을 때만 점프, 공중에서 무한 점프 금지
- **태그를 쓰지 마라.** 프로젝트에 없는 태그로 CompareTag를 호출하면 런타임에 던진다. 접지 판정은 Collider/Raycast나 contact.normal로 하고, 대상 식별이 필요하면 마커 컴포넌트를 GetComponent로 찾아라
- 이 단계에서는 OnTriggerEnter를 쓰지 마라 (트리거 대상이 아직 없다)

[스크립트 산출물]
- Assets/Scripts/MarioMovement.cs
- Assets/Scripts/SideScrollerCamera.cs
- 클래스명과 파일명을 일치시켜라

[Play Mode 합격 조건]
1. 컴파일 오류와 예외가 0건
2. 씬이 Assets/Scenes/Mario1A.unity 로 저장되고 isDirty=false
3. Play Mode 진입 후 런타임 오류가 0건
4. 무입력 0.5초 동안 Player X 변화가 0.05 이하
5. D를 1초 누르면 Player X가 2 이상 증가
6. A를 1초 누르면 Player X가 2 이상 감소
7. Right Arrow 입력으로도 Player X가 증가
8. Space 입력 후 Player Y가 0.5 이상 상승
9. 점프 후 다시 바닥에 착지
10. D만 0.5초 입력한 이동 거리와 D+LeftShift를 입력한 거리를 측정하고, 대시 이동 거리가 더 길 것
11. A+LeftShift에서도 왼쪽 방향으로 같은 대시 효과 확인
12. Player 이동 중 Main Camera X가 같은 방향으로 이동
13. Play 중 Game View 스크린샷 저장
14. 모든 가상 키의 held와 pendingReleases가 비어 있음
15. 검증 종료 후 Play Mode가 반드시 종료됨

[검증 순서]
- 씬과 컴포넌트 확인
- 컴파일 오류 확인
- Play Mode 진입
- 무입력 기준 좌표 측정
- D 이동 측정
- A 이동 측정
- Space 점프의 여러 시점 Y 좌표 측정
- 일반 이동과 Shift 대시 이동 거리를 동일한 시간으로 비교
- 카메라 좌표 변화 측정
- 런타임 오류 확인
- 스크린샷 생성
- 모든 키 해제
- Play Mode 종료
- 최종 상태 확인

합격 조건 중 하나라도 측정되지 않았거나 실패하면 완료라고 보고하지 말고 수정 후 해당 검증을 반복해라.
