CLI의 `--project`로 지정된 격리 프로젝트에서, 새 씬 `Assets/Scenes/Mario14.unity`에 슈퍼마리오 1-1을 닮은 2.5D 횡스크롤 스테이지를 제작해줘.

[격리 및 오염 방지 — 최우선]
- 이 요청의 유일한 최종 씬 경로는 `Assets/Scenes/Mario14.unity`다. `_22`, `_23` 등 다른 씬 경로를 만들거나 사용하지 마라.
- 작업 시작 전에 위 대상 씬이 이미 존재하는지 확인하라. 존재한다면 Unity를 변경·저장·삭제하지 말고 `isolated_target_already_exists`를 보고한 뒤 중단하라. 기존 산출물을 새 작업의 입력으로 사용하지 마라.
- 대상이 없을 때에만 위 경로에 새 Basic Scene을 정확히 한 번 만들고, 그 씬만 열어 작업하라.
- `Assets/Scenes`의 다른 모든 씬은 열거나 변경·저장·삭제하지 마라. 다른 프로젝트로 전환하거나, `--project`로 지정되지 않은 프로젝트의 파일을 사용하지 마라.
- 이 실행에서 생성한 대상 씬은 검증 실패 시 재생성·초기화하지 말고 실패한 항목만 수정한 뒤 재검증하라.
- 씬 외에는 이 요청에 명시한 `Assets/Scripts/MarioMovement.cs`, `Assets/Scripts/SideScrollerCamera.cs`, `Assets/Scripts/CoinPickup.cs`, `Assets/Scripts/GoombaPatrol.cs`만 생성·수정할 수 있다. 그 밖의 기존 에셋과 스크립트는 변경하지 마라.

[중요]
이 요청은 제작, Play Mode 실측 검증, 실패 수정, 재검증까지 포함한다.
모델의 설명만으로 완료하지 말고 모든 합격 조건을 실제 Unity 도구 결과로 확인해라.
검증 실패 시 기존 산출물을 재생성하지 말고 실패 항목만 수정한 뒤 다시 검증해라.
최종 완료 판정은 호스트 검증에 맡겨라.

[스테이지 구조 — 1-1의 뼈대]
- 3D Rigidbody와 Collider를 사용하는 2.5D 횡스크롤 스테이지
- Player의 Z 이동과 회전을 고정
- 오브젝트는 3개 이상이면 `unity_create_gameobjects` 배치 툴을 한 번에 사용해 만든다
- 지면은 세 구간으로 끊고 그 사이를 낙사 구덩이로 둔다
  - Ground1: 위치 (14, -0.5, 0), 크기 (32, 1, 4)
  - Ground2: 위치 (47, -0.5, 0), 크기 (26, 1, 4)
  - Ground3: 위치 (78, -0.5, 0), 크기 (28, 1, 4)
- 파이프 3개를 서로 다른 높이로 세운다 (내려가는 동작은 구현하지 않는다)
  - Pipe1: 위치 (22, 0.5, 0), 크기 (2, 2, 2)
  - Pipe2: 위치 (40, 1.0, 0), 크기 (2, 3, 2)
  - Pipe3: 위치 (52, 1.5, 0), 크기 (2, 4, 2)
- 공중 블록 줄 — 플레이어가 밑을 지나갈 수 있도록 밑면이 y 3.5 이상이어야 한다
  - BrickRow1: 위치 (14, 4, 0), 크기 (6, 1, 2)
  - QuestionBlock1: 위치 (18, 4, 0), 크기 (1, 1, 2)
  - BrickRow2: 위치 (34, 5, 0), 크기 (4, 1, 2)
- 종반 계단 4단 — Step1..Step4를 x 68·70·72·74에 높이 1·2·3·4로
- 목표 지점 Flagpole: 위치 (86, 3, 0), 크기 (0.4, 7, 0.4)
- 코인 3개를 시작 통로 안에 낮게 둔다. 지나가면 사라져야 한다
  - Coin1 (3, 1, 0), Coin2 (5, 1, 0), Coin3 (7, 1, 0) — 각각 크기 (0.5, 0.5, 0.5)
  - 코인의 Collider는 반드시 isTrigger = true여야 하고 Rigidbody를 붙이지 마라
- Goomba 1마리는 Ground2 위에서 좌우로 자동 순찰한다. 위치 (44, 0.4, 0), 크기 (0.8, 0.8, 0.8)
  - 밟는 처리는 구현하지 마라. 순찰만 한다

[검증 통로 — 반드시 지켜라]
- 플레이어 시작 위치는 (0, 1, 0)이다
- **시작 위치 좌우 각 8유닛에는 수직 장애물이 없어야 한다.** 파이프·블록·계단을 그 안에 두지 마라
- 코인은 트리거이므로 통로를 막지 않는다. 그대로 두어도 된다
- 공중 블록은 밑면이 플레이어 머리보다 확실히 높아야 한다

[조작]
- A 또는 Left Arrow: 왼쪽 이동
- D 또는 Right Arrow: 오른쪽 이동
- Space: 점프
- 이동 방향이 존재하는 동안 Left Shift 또는 Right Shift를 누르면 그 방향으로 대시
- 대시 지속시간 0.3초
- 대시 재사용 대기시간 0.6초
- 대시 속도는 일반 이동 속도의 2배
- 대시 중에도 Y 속도는 보존

[입력 구현]
- New Input System의 Keyboard.current만 사용
- legacy UnityEngine.Input API 사용 금지
- Rigidbody.linearVelocity 사용
- 키보드 null 체크
- 바닥에 있을 때만 점프, 공중에서 무한 점프 금지
- undefined tag에 의존하지 말 것
- Ground 판정에 CompareTag("Ground")를 사용하지 말고 Collider/Raycast 기반으로 구현
- 코인 판정도 태그 대신 마커 컴포넌트(CoinPickup)를 GetComponent로 찾아 처리

[스크립트 산출물]
- Assets/Scripts/MarioMovement.cs
- Assets/Scripts/SideScrollerCamera.cs
- Assets/Scripts/CoinPickup.cs
- Assets/Scripts/GoombaPatrol.cs
- 클래스명과 파일명을 일치시켜라
- 기존 파일이 있다면 먼저 읽고 중복 클래스를 만들지 마라

[Player 필수 구성]
- 이름: Player
- Rigidbody
- Collider
- MarioMovement
- MeshRenderer (화면에 보여야 한다)
- Z 위치 고정
- 회전 고정
- 낙사 시 시작 위치로 복귀

[카메라 필수 구성]
- 이름: Main Camera
- Camera
- SideScrollerCamera
- Player의 X/Y를 추종하되 Z는 고정
- 플레이 시작 직후 target이 null이 아니어야 함
- 플레이어와 충분히 떨어져 스테이지가 보이게 한다

[Play Mode 합격 조건]
1. 컴파일 오류와 예외가 0건
2. 씬이 Assets/Scenes/Mario14.unity 로 저장되고 isDirty=false
3. Play Mode 진입 후 런타임 오류가 0건
4. 무입력 0.5초 동안 Player X 변화가 0.05 이하
5. D를 1초 누르면 Player X가 2 이상 증가
6. A를 1초 누르면 Player X가 2 이상 감소
7. Right Arrow 입력으로도 Player X가 증가
8. Space 입력 후 Player Y가 0.5 이상 상승
9. 점프 후 다시 바닥에 착지
10. D만 0.5초 입력한 이동 거리와 D+LeftShift를 입력한 거리를 측정하고, 대시 이동 거리가 더 길 것
11. A+LeftShift에서도 왼쪽 방향으로 같은 대시 효과 확인
12. Player 이동 중 Main Camera X가 같은 방향으로 이동
13. 이동 중 코인에 닿으면 그 코인이 사라질 것
14. Goomba가 입력 없이 스스로 움직일 것
15. Play 중 Game View 스크린샷 저장
16. 모든 가상 키의 held와 pendingReleases가 비어 있음
17. 검증 종료 후 Play Mode가 반드시 종료됨
