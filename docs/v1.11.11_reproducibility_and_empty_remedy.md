# v1.11.11 — 통과의 재현성 측정(n=6) · 빈 remedy 헤더 제거

작성일: 2026-07-30
대상 버전: **v1.11.11**
선행 문서: [v1.11.10](v1.11.10_gate_false_positive.md)

## 1. 배경

v1.11.10 문서 §5의 1번 과제는 "통과의 재현성 확인"이었다. v1.11.10의
`build_stage_success=true`는 **n=1**이었고, 같은 문서가 스스로 세 실행의 씬 배치가
매번 달랐다는 점을 들어 "통과 1회는 안정성의 증거가 아니다"라고 적었다.

이번 사이클은 새 기능을 넣는 대신 **그 주장을 측정**했다. 측정 과정에서 게이트
메시지의 결함이 하나 드러났고, 그것만 고쳤다.

## 2. 재현성 측정

### 2.1 방법

v1.11.10의 E2E 프롬프트에서 씬 경로만 바꾼 파일 5개를 만들어(`...Repro1` ~ `Repro5`)
순서대로 돌렸다. 매 실행은 `.unity`도 `.meta`도 없던 새 경로이고 `--repair-existing`은
쓰지 않았다.

```bash
uv run python main.py --project "C:\Users\park\My project (55)" \
  --prompt-file prompts/platformer_movement_jump_v11110_repro1.txt
```

§1 역할 분담대로 도구 호출은 전부 로컬 `qwen3-coder:30b`가 했고, 판정은 호스트 검증
계층이 만들었다. 호스트는 실행 전 Unity가 유휴 상태(`isPlaying=false`,
`isCompiling=false`)인지 확인한 것 외에 제작·검증 도구를 대신 호출하지 않았다.

### 2.3 차단은 두 번 났고, 둘 다 실제 결함이었다

v1.11.9가 원인을 "예산 문제"로 오진한 전례가 있으므로, 차단은 반드시 스크립트 본문으로
갈라 적는다.

| 실행 | 차단 사유 | 실제 결함인가 |
|---|---|---|
| Repro4 write#1 (1607자) | `no CompareTag("Ground") in a scene created this session` | **예.** 이 세션이 만든 씬에는 Ground 태그가 정의돼 있지 않고, 미정의 태그의 `CompareTag`는 런타임에 예외를 던진다 |
| Repro5 write#1 (1547자) | Update의 `spaceKey.isPressed` 읽기 없음, rising-edge 가드 없음, 위와 같은 `CompareTag` | **예.** v1.11.9가 고친 임펄스 중첩(+19.96)을 되풀이하는 형태 |

**오탐은 0회다.** v1.11.10에서 고친 접지 오탐이 6회 실행 중 한 번도 재발하지 않았다.
두 경우 모두 모델이 **바로 다음 write에서 통과**했다(v1.11.9의 14회 실패와 대조).
파일명 회피나 내용 축소는 한 번도 없었고, 모든 write가 `Assets/Scripts/PlayerMovement.cs`
한 경로였다.

Repro5의 세 번째 write는 차단이 아니다. 통과한 스크립트를 모델이 한 번 더 다듬은
것이고(1845자 → 2053자, 내용 상이) 바이트 동일 재작성 차단에도 걸리지 않았다.

### 2.4 한계

- **모델이 기존 `PlayerMovement.cs`를 읽지 않는다.** 실행 전 디스크에는 직전 통과 실행이
  남긴 `PlayerMovement.cs`가 있었지만, 6회 실행 어디에도 `unity_read_script` 호출이 없고
  매번 다른 해시·길이의 새 내용을 썼다. 남은 파일을 베껴 통과한 것이 아니다. 다만 이
  변수를 **제거하고** 측정하지는 않았다(빈 `Assets/Scripts`에서의 측정은 미실시).
- 씬 배치의 분산은 v1.11.10 때만큼 크지 않았다. 6회 모두 접지가 `col.bounds` 또는 접촉
  노멀 기반이라 씬 배치에 덜 의존한다.
- 여전히 프롬프트 하나, 모델 하나, 프로젝트 하나의 결과다. 다른 요청 형태로 일반화되지
  않는다.

## 3. 변경 내용 — 빈 remedy 헤더

Repro4의 차단 메시지가 이렇게 나갔다.

```text
Missing: no CompareTag("Ground") in a scene created this session (use contact.normal instead).
Fix the first item with exactly this shape:

Do not use the legacy UnityEngine.Input API, and do not create PlayerInput, ...
```

**"이 형태로 고쳐라"라고 해놓고 형태를 주지 않았다.** `_GAP_REMEDIES`에 이 항목의
스니펫이 없어 `fix_first`가 빈 문자열이 됐기 때문이다. v1.11.10이 없애려던 바로 그
"라벨만 주는" 실패가 헤더 아래에 그대로 남아 있었다.

고친 것:

1. `_GROUND_TAG_EXAMPLE` 추가 — 미정의 태그 대신 접촉 노멀로 접지를 판정하는 코드를
   `no CompareTag("Ground")` 라벨에 연결한다.
2. 스니펫이 하나도 없으면 **헤더 자체를 출력하지 않는다.** 빈 본문 위의 지시문은 없는
   것만 못하다.

## 6. 남은 과제

1. **빈 `Assets/Scripts`에서의 측정.** 남은 `PlayerMovement.cs`를 읽지 않는다는 것은
   확인했지만, 제거한 조건에서 재보지는 않았다.
2. remedy 스니펫 채용 비중 검토. 지금 E2E가 측정하는 것은 여전히 "지침을 정확히 적용하는
   능력"이다.
3. Rigidbody 회전을 고정하지 않은 씬의 Z/회전 드리프트를 검증 명세에 넣을지 검토.
4. 점프 상한 10.0의 저중력 씬 오탐 여부.
5. 브리지 도메인 리로드·held-key 재큐잉의 Unity 통합 회귀 테스트.
6. 다른 요청 형태(카메라 추적, 레벨 데이터 등)의 재현성은 측정하지 않았다.
