# v1.11.30 — 접촉 검사 둘을 주입으로 확인하고, 조용히 꺼지던 경로를 막았다

v1.11.29 §4.5는 새 검사 둘이 **단위 테스트로만 확인됐다**고 적었다. 그것을 닫으러
갔더니 검사 하나가 재검증 경로에서 아예 돌지 않고 있었다.

---

## 1. `--repair-existing`에서 검사가 조용히 꺼졌다

`_trigger_handler_scripts()`는 `session_scripts`를 훑어 `OnTriggerEnter`를 찾았다.
그 집합은 **`unity_write_script` 관측으로만 채워진다.** `--repair-existing`은 빌더
단계를 건너뛰므로 집합이 비고, 붙어 있는 스크립트가 무엇이든 검사는 빈 목록을 돌려준다.

기존 씬을 재검증하는 경로 전체에서 A4 검사가 없는 것과 같았다.

```python
candidates |= {f"Assets/Scripts/{item}.cs" for item in self._object_scripts(name)}
```

이 저장소는 **클래스 이름이 곧 파일 이름**이고 스크립트는 `Assets/Scripts/`에 둔다는
규칙을 빌더 프롬프트로 강제한다. 계층에서 읽은 컴포넌트 이름으로 그 경로를 함께
본다. 파일이 없으면 그냥 넘어간다 — 없는 것을 근거로 실패시키지 않는다.

## 2. 검증 — 결함 주입 2건

정상 통과하던 씬(`A1ItemPickup_r13`, 앞선 실행에서 `disappeared=True`)에 결함을
하나씩 넣고 `--repair-existing`으로 재검증했다. v1.11.22가 쓴 방식이다.

### 2.1 트리거를 끈다

```text
주입: Pickup.SphereCollider.isTrigger = false   (핸들러는 그대로)

092911  시도1: ['trigger_handler_without_trigger_collider:Pickup',
                'movement_path_blocked:d']
        시도2: []
        Pickup  gap=−0.501  disappeared=True   [verified]
```

**검출 → repair → 측정이 닫혔다.** repair가 트리거를 되살렸고 재검증에서 아이템이
실제로 사라졌다.

곁들여 `movement_path_blocked:d`가 같이 떴다 — 트리거가 아닌 아이템이 **벽으로
동작해 플레이어를 막는다**는 v1.11.27 §3.1의 설명이 주입 실험에서 재현됐다.

### 2.2 낙하를 일으킨다

```text
주입: Pickup.Rigidbody.isKinematic = false

093104  시도1: ['contact_object_fell_away:Pickup']
        시도2: []
        Pickup y: 0.25 → 0.09 → −13.01 → −36.64   (그 뒤 1.0으로 복구)
        Pickup  gap=−0.747  disappeared=True   [verified]
```

repair는 안내대로 **아이템의 Rigidbody를 통째로 제거**했다(씬에 남은 Rigidbody는
Player 하나뿐). 주입한 결함은 이 수정으로 복원됐다.

### 2.3 안내가 결함을 막고 있었다

`contact_object_fell_away`가 라이브에서 안 터진 이유를 확인했다. 빌더가 아이템에
Rigidbody를 붙이긴 하는데 **`isKinematic = 1`로 만든다** — v1.11.29 §3.3의 안내가
"꼭 필요하면 isKinematic을 true로 둔다"고 적은 그대로다. 결함이 생기지 않아 검사가
돌 일이 없었던 것이지, 검사가 죽어 있던 것이 아니다.

### 2.4 무효였던 재검증 1건

첫 시도(`092538`)는 Editor에 다른 씬이 열려 있어 `wrong_active_scene`으로 끝났고,
검사가 돌기 전에 repair가 씬을 다시 지었다. **그 실행은 근거로 쓰지 않는다.**

### 2.5 단위 테스트

**296 → 297건**, subtest 48건. 전부 통과. 새 1건은 `session_scripts`가 비어도
검사가 도는 것을 고정한다.

### 2.6 측정하지 않은 것

- **핸들러가 플레이어 쪽에 있는 변형은 여전히 단위 테스트뿐이다.** 기록된 6건 중
  4건이 그 형태다. 라이브로 만들려면 `PlayerMovement.cs`에 핸들러를 직접 써 넣어야
  하는데, 그것은 `AGENTS.md` §1이 금지하는 "빌더 대신 게임플레이 코드를 쓰는"
  행위다. 참여자 목록에 `Player`가 들어가는지가 유일한 미검증 지점이고 단위 테스트가
  직접 덮는다
- A0의 임계값은 여전히 미선정 (−0.25 ~ 0.0 구간 공백)
