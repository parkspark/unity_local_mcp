# v1.11.31 — 캡슐을 절반 크기로 재고 있었다, 그리고 경계는 0이 아니었다

A0을 기록에서 검사로 승격하려면 임계값이 필요하고, 임계값을 고르려면 **뒤집히는
지점**이 필요하다. 그것을 찾으러 통제된 스윕을 돌렸더니 두 가지가 나왔다 — 반폭
계산이 캡슐에서 절반이었다는 것과, 경계가 0이 아니라는 것.

---

## 1. 스윕이 드러낸 측정 오차

`A1ItemPickup_r13`(배선 정상, `disappeared=True` 확인됨)에서 **아이템 높이만** 바꿔
간격을 쓸어 담기로 했다. 첫 점에서 물리적으로 말이 안 되는 값이 나왔다.

```text
아이템 y 1.0 → 1.4 로 올렸는데   간격이 −0.747 → −0.901 로 더 음수가 됐다
```

플레이어는 **캡슐**이다.

```text
Unity Capsule 프리미티브 : localScale 1 → 높이 2
호스트의 반폭 계산        : scale / 2 = 0.5
실제 CapsuleCollider     : extents = (0.5, 1.0, 0.5)
```

Cube와 Sphere는 `localScale`이 곧 한 변이라 절반이 맞지만 **캡슐만 다르다.** 그리고
플레이어는 거의 항상 캡슐이므로 **v1.11.27 이후 기록된 모든 접촉 간격에 세로 0.5의
오차가 실려 있었다.** 런타임 플레이어 중심이 y≈1.5라는 것도 이 오차 때문에 안 보였다.

### 1.1 추정을 없앴다

브리지가 콜라이더의 **월드 AABB**를 그대로 내준다. 스케일·회전·콜라이더 오프셋이 이미
반영돼 있어 추정할 것이 없다.

```csharp
if (c is Collider col)
{
    cj["data"] = new JObject {
        ["isTrigger"] = col.isTrigger, ["enabled"] = col.enabled,
        ["center"] = Vec3ToJArray(col.bounds.center),
        ["extents"] = Vec3ToJArray(col.bounds.extents),
    };
}
```

검증 계층은 실측이 있으면 그것을, 없으면 예전대로 `localScale`의 절반을 쓴다 —
구버전 브리지 응답과 콜라이더 없는 오브젝트를 위해서다. 콜라이더가 여럿이면 가장 큰
것을 쓴다(접촉은 어느 하나라도 닿으면 일어난다).

## 2. 경계 스윕 — 뒤집히는 지점은 0이 아니다

같은 씬, 같은 배선, **바뀐 것은 아이템 높이뿐**이다. 전부 repair 없이 통과했다.

| 아이템 y | 표면 간격 | `disappeared` | 영수증 |
|---|---|---|---|
| 2.80 | **−0.199** | False | 094404 |
| 2.65 | **−0.349** | False | 094701 |
| 2.50 | **−0.499** | **True** | 094536 |

**경계는 −0.35와 −0.50 사이다.** 겹침이 0.2~0.35인 구간에서는 획득이 일어나지 않는다.

이것이 스윕을 돌린 이유다. 이전 표본은 −0.8 ~ −1.0에 몰려 있었고 그 구간만 보면
부호가 답인 것처럼 보였다. **부호로 검사를 만들었다면 `y=2.8` 같은 정상 씬이 실패
판정을 받았을 것이다** — v1.11.2가 세운 원칙의 반대 방향 오류다.

## 3. 승격하지 않는다

**여유가 왜 필요한지 설명하지 못했다.**

기하로는 `y=2.8`에서도 닿아야 한다. 영수증에서 역산한 플레이어 중심은 1.499이고,
캡슐 세로 반폭 1.0이므로 머리 끝은 2.499다. 아이템 바닥은 `2.8 − 0.5 = 2.3`이다.
0.2 관통인데 트리거가 걸리지 않았다.

- **곡면 근사 탓이라는 설명은 이 수치에서 안 맞는다.** 접근 방향이 정확히 수직이라
  캡슐 꼭대기와 구 바닥이 정면으로 만나고, 그 지점에서 AABB는 실제 형상과 일치한다
- **경로 표본의 직선 근사도 약하다.** `motion_deltas.d`의 y 델타가 −0.001이다

경계 위치는 표본 셋으로 고정됐지만 **원인을 모르는 채로 임계값을 박지 않는다.**
이 저장소가 v1.11.2부터 지켜 온 것은 "측정하지 않은 것을 성공으로 판정하지 않는다"이고,
그 짝은 "설명하지 못한 것을 실패로 판정하지 않는다"다. A0 승격은 다음 사이클로 넘긴다.

## 4. 검증

### 4.1 라이브 스윕 3회

§2의 표. 세 실행 모두 `verified`, repair 0회. 통제된 것은 아이템 높이 하나다.

### 4.2 단위 테스트

**297 → 298건**, subtest 48건. 전부 통과. 새 1건은 캡슐에서 실측 반폭이 추정을
이긴다는 것과, 콜라이더를 못 본 오브젝트는 예전 경로를 쓴다는 것을 고정한다.
`_box_radius`가 이제 크기가 아니라 반폭을 받으므로 기존 테스트도 그에 맞췄다.

### 4.3 측정하지 않은 것

- **여유의 원인 (§3).** 이것이 다음 사이클의 첫 질문이다
- **경계가 씬마다 같은지 모른다.** 스윕은 한 씬에서만 돌렸다. 플레이어 크기나
  아이템 형상이 다르면 경계도 달라질 수 있다
- **이전 표본의 간격 값은 전부 세로 0.5만큼 낙관적이다.** 재계산하지 않았다 —
  당시 콜라이더 실측이 영수증에 없어서 복원할 수 없다
- 접촉 후보의 좌표는 여전히 시작 시점 한 번만 찍는다
