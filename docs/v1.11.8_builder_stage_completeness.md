# v1.11.8 — 빌더 자체 완결성

## 배경

v1.11.7은 실행 직전에 `.unity`와 `.meta`가 없던 새 경로에서 전체 E2E를 처음
통과했지만 영수증의 `build_stage_success`는 `false`였다. 첫 빌더 산출물은 씬이
저장되지 않아 행동 검증을 시작하지 못했고, repair가 저장·입력 구성·점프 구현을
완성해야 했다.

v1.11.8의 목표는 최종 repair 성공이 아니라 **빌더가 넘긴 최초 산출물이 독립 호스트
검증을 무수정 통과하는 것**이다. 합격 조건은 새 씬 전체 실행에서
`build_stage_success=true`, `attempts=1`, 요청 검사 전부 실측, skipped 0개로 정했다.

## 변경 내용

### 1. 첫 검증 전 빌더 저장 장벽

`agent.py`가 최초 호스트 검증 직전에 활성 씬이 요청의 정규 씬인지 확인한다. Play
Mode라면 종료하고, 빌더가 실제 변경을 만든 경우에만 정규 경로로 씬을 저장한다.
이 단계는 창작이나 repair가 아니라 빌더가 이미 만든 Edit Mode 상태를 영속화하는
결정적 오케스트레이션이다.

`build_stage_success`의 의미도 명확히 했다. 로컬 모델의 서술·자가 검증 루프 종료 여부가
아니라, **빌더가 넘긴 상태의 첫 호스트 검증 실패가 0개인지**를 기록한다. 따라서
산출물이 이미 완전한데 모델이 불필요한 자가 검증을 반복해 iteration 한도에 닿은
경우에도 빌더 산출물 자체의 품질을 정확히 표현한다. `model_loop_completed`는 실행
로그의 별도 진단값으로 남긴다.

### 2. 단순 키보드 요청의 결정적 정책

`task_contract.py`가 A/D, WASD, Space, 방향키처럼 요청에 명시된 키를 추출한다.
PlayerInput/InputAction 아키텍처를 명시하지 않은 단순 요청에는 다음을 강제한다.

- `using UnityEngine.InputSystem`과 직접 `Keyboard.current` 읽기
- 요청에 적힌 모든 키 포함
- `Rigidbody.linearVelocity` 사용과 Y 속도 보존
- Update의 Space 상태 latch와 FixedUpdate의 점프 소비
- Collider bounds 또는 충돌 기반 접지
- 구형 `UnityEngine.Input` API와 미요청 `PlayerInput` 차단
- 새 씬에서 기존 `PlayerMovement`를 재사용하지 않고 이번 세션에서 쓴 스크립트만 부착

브리지 큐에서 짧은 키 전환이 gameplay Update 전에 사라지는 실측을 반영해
`spaceKey.wasPressedThisFrame`은 `spaceKey.isPressed`로 정규화한다. 새 프로젝트에
정의되지 않은 `"Ground"` 태그가 `CompareTag`에서 런타임 예외를 내는 문제도 단순
씬에서는 자기 자신이 아닌 충돌체 검사로 정규화한다. 반면 사용자가 PlayerInput이나
InputAction 콜백을 명시하면 이 직접 입력 정책을 적용하지 않는다.

행동과 검증을 함께 요청한 문장도 builder contract의 Play Mode·입력 실측 대상으로
분류한다. repair contract는 직후 호스트가 동일 검사를 다시 측정하므로, 증거 JSON의
단어 때문에 repair 모델이 전체 자가 검증을 중복하지 않게 했다.

### 3. 입력 브리지 유지와 실행 예산

`UnityMcpBridge.cs`는 누른 키가 있는 동안 완전한 `KeyboardState`를 매 Editor tick
다시 큐잉한다. 물리 키보드 상태 갱신이 합성 press를 덮어써 A/D가 한 프레임만
보이던 문제를 해결했다. tap 만료 시에는 빈 상태를 한 번 큐잉해 키를 해제한다.

빌더가 컴파일 오류를 한 번 고치고 저장·검증까지 마칠 수 있도록 기본
`UNITY_AGENT_MAX_ITERS`는 15에서 30으로 늘렸다.

## 남은 과제

1. `model_loop_completed=false`를 만든 중복 자가 검증과 무효 호출을 줄여 모델 호출
   예산과 E2E 시간을 줄인다.
2. Space가 여러 물리 프레임 유지될 때 점프 impulse가 반복되지 않도록 수동 rising-edge
   latch를 표준화하고, 점프 상승량 상한도 독립 검증 명세로 검토한다. 이번 요청은
   점프 동작을 실측했지만 높이 상한은 요청되거나 측정 기준에 포함되지 않았다.
3. 브리지 Play/Edit 도메인 리로드 재바인딩과 held-key 재큐잉을 Unity 통합 회귀
   테스트로 자동화한다.
4. 정의되지 않은 tag 설정을 성공으로 보고하는 브리지 응답을 명시적 오류로 바꾼다.
