# v1.11.18 — 상호작용 축의 첫 검사, 그리고 새던 탐지기

`docs/STATUS.md` B1("상태 변화 검사군")의 1단계다. 검사를 설계하기 전에 **무엇이
측정되지 않는지부터 재는** 것이 목표였고, 재는 과정에서 그 측정을 담당하던 탐지기
자체가 새고 있는 것을 발견했다.

---

## 1. 배경 — 하네스가 아는 게임은 하나뿐이다

영수증 92건의 검사 조합을 세면 12가지인데 **11가지가 같은 축의 부분집합**이다.

```text
gameplay · movement · bidirectional · jump · jump_landing
camera_follow · camera_fixed_z · boost · level_marker · screenshot
```

전부 "플레이어가 어떻게 움직이는가"다. 축 밖의 성공은 v1.11.16의 `scene_objects`
1건뿐이었다.

그래서 흔한 상호작용 요청 10개를 만들어 정적 추출을 돌렸다
(`prompts/interaction/`). 결과는 **10건 모두 기저(이동·점프) 외 검사 0개**다.

## 2. 결함 A — 미매핑 탐지기가 새고 있었다

v1.11.14가 넣은 `unmapped_requirements`는 "요청에 있으나 어떤 검사도 측정하지 않는
절"을 영수증에 ⚠로 남긴다. 검사를 설계할 재료가 여기서 나온다. 그런데 10건 중
**8건만 잡히고 2건이 조용히 빠졌다.**

| 빠진 절 | 원인 |
|---|---|
| `적을 만들어 좌우로 자동 순찰하게 해줘` | `좌우`가 "이미 측정하는 어휘"라 **거부권** 발동 |
| `떨어지면 시작 위치로 되돌아오게 해줘` | 결과 어휘(되돌아·복귀·리스폰)가 마커에 없음 |

### 2.1 거부권은 아무도 지나지 않는 문을 지키고 있었다

거부권의 근거로 주석에 적힌 예들을 마커에 직접 넣어 보면 이렇다.

```text
부스트로 더 빨라지게      → 마커 False
카메라가 따라오게         → 마커 False
A/D로 좌우로 이동하고     → 마커 False
Space로 점프를 해         → 마커 False
```

**순수 이동 문구는 `_REQUIREMENT_MARKERS`가 이미 거른다.** 거부권이 막으려던 것은
애초에 거기까지 오지 않는다. 대신 같은 낱말이 **플레이어가 아닌 대상**을 가리키는
절을 묵살했다.

코퍼스 전체에서 거부권이 묵살한 절은 5개이고, 그중 **3개가 진짜 공백**이었다.

```text
[좌우] 적(빨간 캡슐)을 하나 만들어 좌우로 자동 순찰하게 해줘
[이동] 이동과 점수 획득이 실제로 되는지 검증까지 끝내줘
[카메라] 카메라가 보드 전체를 담도록 배치하고
```

### 2.2 나머지 2개는 두 오탐이 상쇄된 것이었다

```text
[keyboard,input] - New Input System의 Keyboard.current만 사용
[키보드]         - 키보드 null 체크
```

이 구현 지시문이 왜 마커에 걸렸는지 보면 — **`보드`가 "키보드" 안에서, `board`가
"Keyboard.current" 안에서 매칭된다.** 마커 오탐을 거부권 오탐이 우연히 지우고
있었고, 그래서 둘 다 보이지 않았다.

### 2.3 수정

- `(?<!키)보드` · `(?<!key)board` — 키보드는 보드가 아니다
- 낙사 복귀 어휘 추가 (`되돌아|복귀|리스폰|respawn|시작 위치로`)
- **거부권 제거.** 대신 `_CHECK_COVERAGE`를 넣었다 — 어휘 가족이 아니라 **검사
  이름**에 묶인 덮개다. 켜져 있는 검사가 덮는 문구를 절에서 지운 뒤 마커가 남는지
  다시 본다. 남으면 여전히 미매핑이다

탐지 **8/10 → 10/10**, 기존 코퍼스의 오탐 2건 제거.

`unmapped_requirements`는 판정에 들어가지 않는 순수 기록이므로(`verification.py`의
영수증 필드) 이 수정에 판정 위험이 없다.

## 3. 결함 B — 스스로 움직이는 것을 보는 검사가 없다

수정한 탐지기로 라이브 2건을 돌렸다. **둘 다 `verified`, 검사 7개 전부 통과,
failures 없음.**

### 3.1 코인/점수 — 기능이 아예 없는데 통과했다

영수증 `logs/receipts/2026/08/03/20260803_002742` 계열, 104초.

```text
scene_objects : ['Player', 'GroundPlatform', 'Coin_1', 'Coin_2', 'Coin_3']
measured      : 7개 전부 통과
⚠ unmapped    : 코인 3개를 공중에 배치하고 / 코인에 닿으면 점수가 1 올라가게
```

코인은 오브젝트로 만들어졌다. 그런데 프로젝트 전체에서:

```text
Assets/Scripts/ 안의 score·Coin 구현 : 없음
ProjectSettings/TagManager.asset     : tags: []
```

**획득도 점수도 구현되지 않았다.** 모델이 중간에 `OnTriggerEnter`로 코인 로직을
썼는데, 입력 스크립트 게이트에 차단당하고 다시 쓰면서 그 로직이 통째로 사라졌다.
v1.11.17이 고친 "차단 후 재작성이 멀쩡한 코드를 깨뜨린다"의 두 번째 사례이고,
이번에는 사용자가 요청한 기능이 날아갔다.

### 3.2 적 순찰 — 기능은 됐는데 아무도 보지 않았다

영수증 `20260803_002929` 계열, 65초. 이쪽은 `EnemyPatrol.cs`가 제대로 만들어졌고
`Enemy`에 붙었다. **기능은 동작하는데 그것을 보는 검사가 없었다.**

두 실행의 유일한 신호가 §2에서 고친 ⚠ 줄이었다. 고치기 전이었다면 순찰 건은 아무
표시 없이 통과했다.

## 4. 변경 내용

### 4.1 `autonomous_motion` — 입력 없이 움직이는가

요청이 순찰·자동 이동을 말하면 붙는다. Play Mode에서 **입력을 주기 전에**, 계층에서
얻은 Player 아닌 루트 오브젝트들의 위치를 0.8초 간격으로 두 번 잰다. 하나라도
0.15유닛 이상 움직였으면 통과다.

| 결과 | 실패 코드 |
|---|---|
| 표본을 못 얻음 | `autonomous_motion_not_measured` |
| 아무것도 스스로 움직이지 않음 | `no_object_moved_on_its_own` |

설계에서 정한 것 세 가지.

- **대상을 이름 규칙으로 정하지 않는다.** 요청은 "적"이라 하고 모델은 Enemy·
  Patroller·Monster 중 무엇으로든 부른다. v1.11.16이 넣은 계층 판독에서 이름을
  가져온다
- **Player는 후보에서 뺀다.** 호스트가 입력으로 직접 미는 대상이라 "스스로"가 아니다
- **입력 측정 전에 잰다.** 이동 측정이 시작되면 물리·충돌로 다른 오브젝트도 밀려나,
  스스로 움직인 것인지 밀린 것인지 구분할 수 없게 된다

Play Mode 증명이 필요하므로 `behaviour_checks()`의 정적 집합에 넣지 **않았다**.

### 4.2 접촉 대상 식별 — 태그가 아니라 마커 컴포넌트

상호작용 10건 중 7건이 "무엇에 닿으면"이다. 대상을 식별하려면 태그가 필요한데
`tags: []`이고 태그를 만드는 도구가 없다. `policy_lint.py`는 미정의 태그를 쓰는
`CompareTag`를 전부 막는다 — 런타임에 던지기 때문이다.

**도구를 늘리는 대신 이미 되는 길을 열었다.** 한 줄짜리 마커 컴포넌트
(`public class Coin : MonoBehaviour {}`)를 붙이고 `other.GetComponent<Coin>()`으로
검사하면, 프로젝트 태그가 필요 없고 런타임에 던지지 않으며 이름을 바꿔도 살아남는다.
빌더 프롬프트에 이 패턴과 "접촉 법선은 방향만 알려주지 정체를 알려주지 않는다"를
넣었다. 붙이지 않은 컴포넌트에 대한 경고도 함께 넣었다 — 순찰 실패의 가장 흔한
원인이 스크립트만 쓰고 `add_component`를 빠뜨리는 것이다.

## 5. 검증

### 5.1 단위 테스트

**242 → 251건**, subtest 43건. 전부 통과.

- `AutonomousMotionTests` 8건 — 검사 부착, Play Mode 분류, Player 제외, 정지한 적
  실패, 순찰하는 적 통과와 영수증 기록, 미표본 구분, 이동만 있는 요청에 안 붙음,
  수정 안내가 `add_component`를 짚는지
- 탐지기 3건 — 측정 어휘가 같은 절의 미측정 부분을 보증하지 않을 것, 낙사 복귀 기록,
  키보드는 보드가 아닐 것
- 기존 1건 수정 — 순찰 절이 이제 `autonomous_motion`에 덮이므로, 그 테스트가 지키던
  결함을 아직 검사가 없는 절(점수)로 옮겨 표현했다

### 5.2 라이브

수정 전 같은 요청이 검사 7개로 통과했던 자리다.
영수증 `logs/receipts/2026/08/03/20260803_225114_694_9a9c7b9206.json`, 82.2초,
repair 0회.

```text
requested = scene_objects, player_visible, gameplay, autonomous_motion,
            movement, bidirectional, jump, components:Player
measured  = 8개 전부          skipped = []        failures = []
autonomous_motion : {'object': 'Enemy', 'distance': 1.6458}
⚠ unmapped        : []        ← 이제 덮이므로 비었다
```

`EnemyPatrol.cs`의 `moveSpeed = 2f`에 측정 구간 0.8초를 곱하면 1.6이다. **실측
1.6458이 그 값과 맞는다.**

### 5.3 측정하지 않은 것

- **실패 경로는 라이브로 재현하지 않았다.** 순찰 스크립트를 붙이지 않은 상태에서
  `no_object_moved_on_its_own`이 뜨고 repair가 고치는지는 단위 테스트로만 확인했다
- **표본 1회다.** 통과 1건이지 재현성 측정이 아니다
- **마커 컴포넌트 패턴은 라이브로 확인하지 않았다.** 빌더 프롬프트에 넣었을 뿐,
  모델이 실제로 그렇게 쓰는지는 접촉 검사가 생긴 뒤에 판단할 수 있다

## 6. 이 사이클이 남긴 것

열린 항목은 [STATUS.md](STATUS.md)에 있다(`AGENTS.md` §3.1).

- **A** 접촉 반응(코인·아이템·적 처치·깃발) 검사가 새 항목으로 열렸다. §3.1이 그
  라이브 증거다. 막힌 곳은 **호스트가 접촉을 결정적으로 일으킬 수 없다**는 것 —
  코인이 어디 있는지 모르고 키 입력밖에 못 준다. 약한 검사를 급조하지 않는다
- **A** §3.1의 "차단 후 재작성이 요청 기능을 지운다"는 v1.11.17 사례의 재발이다
- **B** `autonomous_motion`의 실패 경로 라이브 확인과 재현성
- **F** v1.11.14의 미매핑 기록 공백, "상호작용 요청이 무엇을 뽑는지 모른다"
