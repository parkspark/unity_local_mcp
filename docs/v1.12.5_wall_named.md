# v1.12.5 — 재현성을 재니 `verified`는 1/6이었고, 원인은 벽이었다

v1.12.4의 `verified`는 1회였다. 같은 프롬프트를 5회 더 돌렸다. **0/5.** 실패한
회차들의 실측을 겹쳐 놓으니 원인이 하나로 모였다 — **빌더가 시작 통로 안에 플랫폼을
낮게 놓고, 호스트는 그것을 부스트 결함이라고 말한다.** 그 벽을 이름으로 부르게 하자
**1/5**가 됐고, 게이트가 발동한 3회는 전부 다음 사이클에 배치가 고쳐졌다.

---

## 1. 재현성 측정 — 0/5

v1.12.4가 통과한 [prompts/v112_plan6.txt](../prompts)를 **씬 이름만 바꿔** 5회
재실행했다(`v112_repro1..5`). 매 회차 직전 `PlayerMovement25D.cs`·
`SideScrollerCamera.cs`를 지워 시작 상태를 맞췄다 — 안 지우면 통과한 회차의
known-good 스크립트를 물려받아 재현율이 부풀려진다.

```text
회차     판정    측정/미측정  사이클  마지막 실패
plan6   verified   17 / 0      3     —
repro1  failed     17 / 0      4     movement_path_blocked:d, boost_distance_too_short
repro2  failed      8 / 9      4     policy_lint 루프로 Play Mode 측정 자체를 못 함
repro3  failed     17 / 0      4     boost_distance_too_short, left_boost_...
repro4  failed      6 / 11     3     자기 스크립트를 지워 verification_regressed
repro5  failed     17 / 0      4     boost_distance_too_short (3·4사이클 연속)
```

**`verified` 0/5.** 그리고 v1.12.4가 산 것은 따로 확인됐다 —
`player_fell_no_ground_in_scene`이 2회 발동했고 **둘 다 다음 사이클에 repair가 씬을
고쳐 복구**했다. 낙하 실패에 사이클이 눌러앉은 회차는 0건이다.

## 2. 세 회차가 같은 원인이었다

전부 측정한 세 회차의 마지막 사이클 기하다.

```text
                Platform1              플레이어 오른쪽 이동
verified(plan6) x[3..7] 밑면 y=2.00     d +6.84   통과
repro1          x[3..7] 밑면 y=0.90     d +2.500
repro5          x[3..7] 밑면 y=0.75     d +2.500
```

플레이어(반폭 0.5, 중심 y 0.466)의 머리는 0.966이다. 밑면이 그보다 낮은 플랫폼이
x=3에 서 있으면 **x=2.5에서 정확히 막힌다.** 요청은 "시작 위치 오른쪽 8유닛은
평지"라고 썼고, 빌더는 x=5에 놓았다. `verified` 1회는 그 밑면이 우연히 2.0이라
밑을 지나간 것이다.

막힌 방향에서는 부스트가 빨라져도 거리가 같다. 그래서 증상은
`boost_distance_too_short`로 나오고, **repair는 멀쩡한 부스트 코드를 고치러 간다.**
repro5는 같은 실패로 두 사이클을 태웠다.

### 이름을 줄 검사는 이미 있었는데 문턱에서 갈렸다

`movement_path_blocked`는 v1.11.15부터 있고 안내문도 정확하다 — "스크립트 결함이
아니라 배치 문제다". 발동 조건이 d/a 비율 0.5 미만이었다.

```text
repro1  2.500 / 5.078 = 0.492   발동
repro3  2.500 / 4.980 = 0.502   침묵
repro5  2.500 / 4.383 = 0.570   침묵
```

**물리적으로 같은 원인이 문턱을 사이에 두고 1/3만 이름을 받았다.** 비율은 원인의
대리 지표이고, 원인 자체는 영수증의 `contact_candidates`에 기하로 이미 들어 있었다.

## 3. 변경 — 빈 구간을 기하로 판정한다

문턱을 내리지 않았다. 내리면 0.43~0.95의 "빈 구간"에 있는 정상 표본까지 끌어온다.
대신 **그 구간에서만** 멈춘 자리를 본다.

```text
비율 < 0.50            기존대로 비율만으로 확정
0.50 ≤ 비율 < 0.85     멈춘 자리에 벽이 있을 때만 확정   ← 신규
비율 ≥ 0.85            건드리지 않는다 (정상 구간은 0.96 이상)
```

`blocking_object()`는 두 조건이 **동시에** 성립할 때만 벽으로 본다.

```text
멈춘 표면과 벽면이 맞닿아 있다   간격 −0.25 ~ 0.35
세로로 실제로 겹친다             겹침 > 0.05
```

밟고 서 있는 바닥은 맞닿기만 하고 겹치지 않으므로 두 번째에서 빠진다. 진행 방향
뒤에 있는 것도 보지 않는다.

찾은 벽은 **이름으로** 나간다 — 영수증 `blocking_objects`, 그리고 교정 안내에
"막은 것은 `Platform1`이다. position.x를 8유닛 밖으로 옮기거나 밑면이 플레이어
머리보다 높도록 y를 올려라". 벽이 확인되면 부스트 안내에서 **코드 수정 항목을
뺀다** — "부스트 거리 부족은 결과이지 원인이 아니다".

## 4. 검증

### 4.1 라이브 — 같은 조건 5회 재측정

동일 절차로 `v112_repro6..10`을 돌렸다.

```text
회차      판정     측정/미측정  사이클  게이트 발동   결과
repro6   failed     17 / 0      4     Platform1    벽 제거됨, 부스트 1.39로 실패
repro7   verified   17 / 0      4     Platform_1   벽 제거됨 → 다음 사이클 통과
repro8   failed     17 / 0      3     Platform1    벽 제거됨, left_boost 회귀
repro9   failed     17 / 0      4     —            부스트 1.07

```

- **`verified` 0/5 → 1/5.** 표본이 작다 — 이 차이 하나만으로는 개선을 주장할 수 없다
- **게이트는 발동한 3회 전부에서 다음 사이클에 벽이 사라졌다(3/3).** 그 뒤 d/a가
  ±4.93 / ±4.86처럼 대칭으로 돌아왔다. 이름을 준 것이 배치 수정으로 이어졌다
- **오탐 0.** repro7의 통과한 마지막 사이클에도 `blocking_objects`에 이름이 남지만
  비율 0.92라 실패를 만들지 않았다 — 기록은 하고 판정은 안 하는 설계 그대로다
- 측정 완결성이 **3/5 → 5/5**로 올라갔다(전 회차 17/0). 이 배치의 우연일 수 있다
- `player_fell_no_ground_in_scene`은 이번에도 2회 발동해 **2회 다 복구**했다

## 5. 이 측정이 새로 드러낸 것 — 부스트 문턱이 요청과 어긋난다

벽이 사라진 뒤 남은 실패는 전부 부스트 비율이고, 값이 문턱 바로 밑에 몰려 있다.

```text
repro6   3.50 / 2.51 = 1.39      실패      문턱 1.4
repro8   3.47 / 2.48 = 1.40      실패
repro10  3.54 / 2.54 = 1.39      실패
repro7   3.64 / 2.54 = 1.43      통과
```

요청은 **부스트 지속 0.18초·속도 2배**라고 썼고, 호스트는 **0.5초 구간**의 거리를
비교한다. 요청대로 정확히 구현하면 비율의 상한은

```text
(0.18 × 2 + 0.32) / 0.5 = 1.36
```

**요청을 완벽히 지킨 구현이 문턱 1.4를 넘을 수 없다.** 통과한 회차들은 지속시간이나
배수를 요청보다 크게 잡아 넘긴 것이다. 판정이 구현 품질이 아니라 **요청 위반 정도**로
갈리고 있다.

문턱을 내리는 것은 통과 기준을 낮추는 것이므로 이 버전에서 하지 않았다. 선택지는
둘이다 — 측정 구간을 `boost_duration`이 아니라 **요청의 부스트 지속시간**에 맞추거나,
요청에서 읽은 지속·배수로 **기대 비율을 계산**해 문턱을 세우거나. STATUS A9에 남긴다.
