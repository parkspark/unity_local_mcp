# v1.11.2 — 검증 명세 신뢰성 (P0)

작성일: 2026-07-28
대상 버전: **v1.11.2**
선행 문서: [v1.11.1 진행 현황 및 개선 보고서](v1.11.1_status_and_improvement_report.md) §4.1, §5 P0

## 1. 해결한 결함

v1.11.1 보고서가 최우선으로 지목한 **검증 공집합 성공**을 수정했다. 기능이 실패하는 것보다
위험한, **측정하지 않은 것을 성공으로 판정하는** 결함이다.

### 실제 증거

`logs/receipts/2026/07/23/20260723_152344_131_a24a11b9d2.json`:

```
status               = verified      ← 성공으로 판정
failures             = []
build_stage_success  = False         ← 빌드 단계는 실패했는데
spec.require_jump    = False         ← 점프 검증이 꺼져 있고
spec.require_gameplay= False
evidence.runtime.played = False      ← Play Mode를 아예 돌리지 않음
request = "…Space 점프가 동작하지 않는다. … 점프가 잘 작동하도록 수정하고 검증한다."
```

점프 수정을 명시적으로 요청했는데도 검증 조건이 전부 꺼졌고, 실패 목록이 비었다는
이유만으로 `verified`가 됐다.

### 근본 원인

[verification.py](../verification.py)의 명세 추출이 모든 행동 검증을 `게임` 계열
키워드에 종속시켰다.

```python
game     = any(word in lower for word in _GAME_WORDS)
movement = game and any(...)   # ← 게임 키워드가 없으면 전부 False
jump     = game and any(...)
camera   = game and any(...)
```

버그 리포트는 보통 `게임`이라는 단어를 쓰지 않는다("Space 점프가 동작하지 않는다").
따라서 실제 버그 수정 요청일수록 검증이 꺼지는 역설적 구조였다.

## 2. 변경 내용

### 2.1 행동 키워드를 게임 키워드와 분리 (P0-1)

행동 동사는 그 자체로 강한 신호로 취급하고, 개체 명사(`플레이어`)만 게임 문맥을 요구한다.

| 구분 | 단어 | 게임 키워드 필요 |
|---|---|---|
| 이동 | 이동, 움직, 걷, 달리, movement, walking, running | 아니오 |
| 이동(문맥) | 플랫포머, 횡스크롤, 플레이어, player | 예 |
| 점프 | 점프, jump, jumping, 착지, landing | 아니오 |
| 카메라 | 카메라, camera | 게임 **또는** 추종/따라/follow |
| 부스트 | 부스트, boost, dash, 대시 | 아니오 |

`_has_word()`는 한국어를 부분 문자열로, 영문을 **라틴 문자 경계**로 매칭한다.
`\b`를 쓰면 한글이 단어 문자로 취급되어 `Main Camera는`이 `camera`에 매칭되지 않으므로,
경계를 `(?<![a-z0-9])…(?![a-z0-9])`로 정의했다. 이로써 `remove`가 `move`에
오탐하지 않으면서 한국어 조사가 붙은 영어 단어도 잡는다.

### 2.2 행동 조건 → Play Mode 강제 (P0-2)

행동 검증 조건이 하나라도 추출되면 `require_gameplay=True`. 실행하지 않은 검사는
통과로 계산될 수 없다.

```python
behaviour = movement or jump or camera or boost
require_gameplay = game or level or behaviour
```

부수적으로 `require_boost`는 일반 이동 대비 비율로 측정하므로 `require_movement`를
함의하고, `require_jump_landing`은 점프 궤적의 일부이므로 `require_jump` 없이는
요청되지 않는다. `Player` 컴포넌트 요구도 `movement or jump`로 확장했다.

### 2.3 측정 조건 0개면 verified 금지 (P0-3)

런타임 동작 언어를 썼는데 측정 가능한 조건을 못 뽑으면 `verification_spec_empty`로
실패 처리한다. 매핑하지 못한 행동 요청(예: "적 AI 충돌 판정이 동작하지 않는다")을
조용히 성공시키지 않기 위한 backstop이다.

```python
if spec.enabled and spec.behaviour_requested and not spec.behaviour_checks():
    failed.append("verification_spec_empty")
```

이 실패는 모델이 고칠 수 없는 호스트 측 추출 공백이므로 [agent.py](../agent.py)의
자동 수정 루프에서 **즉시 중단**한다(예산 낭비와 불필요한 프로젝트 변경 방지).
사용자에게는 검증 대상을 구체적으로 지정하라는 안내를 출력한다.

또한 `고치/고쳐/해결/repair`를 빌드 동사에 추가했다. 이전에는
"부스트가 동작하지 않는다. **고쳐줘**"가 빌드 요청으로 인식되지 않아 검증
오케스트레이션 자체가 건너뛰어졌고, 모델이 스스로 성공을 선언할 수 있었다.

### 2.4 영수증에 요청/측정/누락 검사 명시 (P0-5)

`requested_checks`, `measured_checks`, `skipped_checks`를 영수증 최상위에 기록한다.
빈 검증이 빈 실패 목록 뒤에 숨지 않고 한눈에 드러난다.

```json
"requested_checks": ["gameplay", "jump", "jump_landing", "components:Player"],
"measured_checks":  [],
"skipped_checks":   ["gameplay", "jump", "jump_landing", "components:Player"]
```

`measured_checks`는 통과 여부와 무관하게 **실제 측정값이 존재하는** 검사만 센다.
성공 보고에는 측정 항목을, 실패 보고에는 미측정 항목을 함께 출력한다.

### 2.5 회귀 테스트 (P0-4)

`tests/test_verification.py::BehaviourSpecExtractionTests` — 실제 실패 영수증의
요청 문자열을 그대로 고정 데이터로 사용한다.

- 점프 수정 요청이 `require_jump` / `require_jump_landing` / `require_gameplay`를 켠다
- 같은 요청이 Play Mode 없이는 `play_mode_not_tested`로 실패한다
- 짧은 한국어 이동/카메라/부스트 수정 요청의 조건 추출
- `remove`가 이동 검증을 켜지 않는다 (영문 경계)
- `Player 이름 수정`, `Foo.cs 오타 수정`이 Play Mode를 요구하지 않는다 (과잉 검증 방지)
- 매핑 불가 행동 요청이 `verification_spec_empty`로 거부된다
- `check_report()`가 측정/미측정을 정확히 분리한다
