# v1.11.25 — 점이 아니라 경로로 재고, `repair_aborted`가 라이브에서 발동했다

A0의 3단계다. 거리 기록의 정확도 결함을 하나 고쳤고, 그 과정에서 v1.11.20의
`repair_aborted`가 처음으로 실제 실행에서 작동했다.

---

## 1. 결함 — 표본이 점이라 지나간 곳을 놓쳤다

v1.11.24의 표에서 `Coin_1`이 이상했다.

```text
Coin_1  좌표 (2, 2, 0)   거리 2.052
```

플레이어는 `x 0 → 4.95`를 지나갔다. 코인 바로 아래를 통과했으니 수직 거리는 1.0이어야
한다. 원인은 `player_samples`가 **측정 구간의 양 끝점만** 담는다는 것이다.

```text
남는 표본 : (0, 1, 0)  (4.95, 1, 0)  …
없는 것   : 그 사이의 (2, 1, 0)
```

점만 보면 실제로 통과한 지점이 기록에서 사라진다. **A0가 잡으려는 것이 바로 "지나갔는데
반응이 없다"이므로, 이 결함은 목표를 정면으로 막는다.**

## 2. 수정 — 선분으로 재되, 지어내지 않는다

측정 구간을 선분으로 다루고 점-선분 거리를 쓴다. 다만 **아무 표본끼리 이으면 안 된다** —
구간 사이에는 `restart_play()`로 플레이어가 스폰으로 되돌아가므로, D 측정의 끝과 A 측정의
시작을 이으면 실제로 지나가지 않은 경로를 지어내게 된다.

"한 번의 연속 이동"이 보장된 쌍만 쓴다.

- `motion_before[label] → motion_after[label]` (D·A·부스트 각 구간)
- 점프: `jump_before → (같은 X, jump_peak_y, 같은 Z)`

## 3. 오프라인 복원은 믿을 수 없었다 — 정정

수정 효과를 기록된 영수증으로 재생해 봤더니 `Item`이 1.921 → **0.001**로 나왔다.
"관통했는데 안 사라졌다"는 강한 신호로 보였다.

**그 수치는 허수였다.** 영수증에는 이동 **델타**만 있고 시작 좌표가 없어서, 복원할 때
플레이어가 `(0, 1, 0)`에서 출발했다고 가정했다. 실제 시작 위치는 달랐다.

새 코드로 라이브를 다시 돌린 실측이다.

| 오브젝트 | 거리 | 사라짐 | scripts |
|---|---:|---|---|
| Item | **1.207** | False | `['Collectible']` |
| Item | 1.210 | False | `['Collectible']` |
| Item | **0.773** | False | `['Collectible']` |
| Ground | 1.485 · 1.486 · 1.239 | False | `[]` |

0.001이 아니라 0.773~1.21이다. 관통하지 않았으므로 **`Item`이 고장이라고 말할 수 없다.**

v1.11.24 §1의 표는 점 기반 수치라 그대로 두되, 이 문서가 정정한다.

## 4. `scripts` 필드는 의도대로 갈랐다

v1.11.24가 넣은 필드에 처음으로 표본이 붙었다.

```text
Item    scripts = ['Collectible']   ← 상호작용 대상
Ground  scripts = []                ← 구조물
```

구조물과 대상이 스크립트로 정확히 갈린다. v1.11.24 §2.1이 지목한 첫 번째 장애물의
재료가 확보됐다.

## 5. `repair_aborted`가 라이브에서 발동했다 (STATUS B0)

같은 수집의 두 번째 실행에서 Ollama가 끊겼다.

```text
verification_finished  policy_lint:undefined_compare_tag:...:Coin (외 6건)
warning                독립 검증 미통과 7건 — 실패 항목 자동 수정 1/3
warning                Ollama 응답이 중간에 끊겨 모델 호출을 재시도합니다 (1/1)
warning                자동 수정이 중단됐습니다(ResponseError). 지금까지의 측정은 영수증에 남깁니다
run_finished           failed 33.8초
```

**영수증이 남았다.**

```text
status   = failed  33.8초
measured = ['scene_objects', 'player_visible', 'components:Player']
failures = policy_lint:undefined_compare_tag:... / blocked:*×6 / repair_aborted:ResponseError
```

2026-08-05 오전 같은 상황에서는 예외가 영수증 기록 지점을 건너뛰어 **완료된 측정이 통째로
사라졌다.** 이번에는 측정 3건과 중단 사유가 함께 보존됐다. v1.11.20의 수정이 의도대로
동작한다.

## 6. 검증

### 6.1 단위 테스트

**273 → 276건**, subtest 48건. 전부 통과.

- 구간 한가운데를 지나간 것이 거리에 반영됨(실측 2.052 → 1.0 형태)
- **분리된 측정을 지어낸 경로로 잇지 않음** — `restart_play` 때문에 반드시 지켜야 한다
- 점프가 같은 X의 수직 선분으로 잡힘

### 6.2 라이브

§3의 표(3회 측정)와 §5의 영수증. 프롬프트 `prompts/interaction/seg_*.txt`.

### 6.3 측정하지 않은 것

- **여전히 임계값을 고를 수 없다.** 사라진 표본은 통틀어 하나(`Coin_2`)뿐이고, 이번
  수집에서는 하나도 나오지 않았다
- **관통 표본이 없다.** 0.773이 가장 가까웠고, 그 거리에서 안 사라진 것은 정상일 수 있다
- 두 실행 모두 `failed`로 끝나 접촉 검사의 재료 외에는 얻은 것이 없다

## 7. 이 사이클이 남긴 것

- **A0** 거리 정확도와 대상 식별은 갖췄다. 남은 것은 **관통 표본**이다 — 지금 배치에서는
  호스트의 이동 경로가 오브젝트를 정확히 통과하는 일이 드물다
