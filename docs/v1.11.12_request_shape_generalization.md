# v1.11.12 — 다른 요청 형태에서 드러난 결함 셋

작성일: 2026-07-30
대상 버전: **v1.11.12**
선행 문서: [v1.11.11](v1.11.11_reproducibility_and_empty_remedy.md)

## 1. 배경

v1.11.11은 "A/D 이동 + Space 점프" 프롬프트 하나로 9/9를 측정했고, 문서 §6의 1번 과제로
**다른 요청 형태의 재현성**을 남겼다. 그 숫자가 파이프라인 전체의 건강을 뜻하는지,
아니면 한 요청 형태에 맞춰진 것인지 구분되지 않았기 때문이다.

이번 사이클은 **카메라 추종** 요청으로 같은 측정을 했다. 결과는 후자였다.

## 2. 측정 — 카메라 추종 요청 (v1.11.11)

프롬프트: 새 빈 씬 + Player(캡슐) + 바닥 + A/D 이동 + **Main Camera가 Player를 따라오게**
+ 검증까지. 요청 검사 항목은 `gameplay, movement, bidirectional, camera_follow,
components:Main Camera, components:Player`로 점프 형태와 다르다.

매 실행 새 씬 경로, `--repair-existing` 없음, 실행 직전 `Assets/Scripts` 정리
(`LevelLoader.cs` 제외).

| | Cam1 | Cam2 | Cam3 |
|---|---:|---:|---:|
| `status` | **failed** | verified | verified |
| `build_stage_success` | **false** | **false** | **false** |
| 검증 사이클 | 4 (rollback) | 2 | 3 |
| 측정된 검사 | 2/6 | 6/6 | 6/6 |
| 경과 | 92.9초 | 79.7초 | 106.5초 |

**빌더 자체 완결성이 0/3이다.** 점프 형태의 9/9와 정반대다. v1.11.11의 숫자는
파이프라인의 건강이 아니라 **한 요청 형태에 맞춰진 성숙도**였다.

영수증: `logs/receipts/2026/07/30/` — `20260730_100836_491_d3637503ee.json`,
`..._101037_833_afa1bf9ce3.json`, `..._101244_355_68fdee09a6.json`

세 실행이 서로 다른 결함 셋을 드러냈다.

### 2.1 결함 A — 빈 씬에는 카메라가 없다 (3/3)

세 실행 모두 첫 검증이 `component_missing:Main Camera:Camera`로 실패했다. 모델은
`unity_create_scene`을 `template="empty"`로 호출했고, 빈 템플릿은 카메라도 광원도 주지
않는다. 카메라가 없으면 `camera_follow`뿐 아니라 `gameplay`·`movement`까지 **측정 이전에
차단**된다(`component_not_ready:Main Camera`).

원인은 요청 문구다. 사용자는 "새 **빈** 씬"이라고 썼고 모델은 그것을 `template="empty"`로
옮겼다. 사용자가 말한 "빈"은 게임플레이 오브젝트가 없다는 뜻이지 카메라가 없다는 뜻이
아니다.

### 2.2 결함 B — 접지 태그 게이트가 점프 요청에만 걸려 있었다 (2/3)

Cam1과 Cam2가 런타임에 `Tag: Ground is not defined`를 던졌다.

```text
UnityEngine.GameObject:CompareTag (string)
PlayerMovement:OnCollisionEnter (UnityEngine.Collision) (at Assets/Scripts/PlayerMovement.cs:47)
UnityEngine.Physics:OnSceneContact (...)
```

v1.11.8이 막아둔 결함인데, 게이트 코드가 `if "spaceKey" in self.direct_keyboard_keys:`
블록 **안에** 있었다. 점프가 없는 요청은 이 검사에 도달하지 못한다.

미정의 태그는 **씬의 성질이지 점프의 성질이 아니다.** 누가 호출하든 던진다.

### 2.3 결함 C — 런타임 오류가 컴파일 오류로 계산됐다 (Cam1을 failed로 만든 원인)

가장 손해가 큰 결함이다. `VerificationContract`는 콘솔을 읽을 때 **Play 중이었는지**로
오류의 성격을 갈랐다.

```python
if self.playing and self.waited:   ... 런타임 오류
elif not self.playing:             ... 컴파일 오류
```

Play를 멈춘 뒤 콘솔을 읽으면 방금 끝난 세션의 런타임 오류가 그대로 남아 있고, 그것이
**컴파일 오류로 기록된다.** Cam1의 `compile.unique_errors`에는 `OnSceneContact` 스택을
가진 `Tag: Ground is not defined`가 들어 있고 `compile_errors:2`가 찍혔다.

결과는 연쇄였다. `compile_errors > 0` → 모든 검사가 `compile_not_ready`로 차단 →
측정값이 사라지니 `verification_regressed` → rollback → 최종 `failed`. **고칠 수 있는
런타임 오류 하나가 실행 전체를 되돌렸다.**

## 3. 변경 내용

### 3.1 콘솔 분류를 실행 상태에서 진단 내용으로 (결함 C)

`_compile_diagnostics()`가 컴파일러 진단만 골라낸다 — `error CS####`, `compiler errors`,
`Build completed with a result of 'Failed'`. 나머지는 방금 끝난 Play의 잔여물이므로
**런타임 집계에 합류**시킨다. 사라지지 않고, 컴파일 게이트만 막지 않는다.

판정 기준을 "언제 물어봤나"에서 "무엇이 적혀 있나"로 옮긴 것이다.

### 3.2 접지 태그 검사를 씬 조건으로 (결함 B)

`CompareTag("Ground")` 검사를 점프 분기 밖으로 꺼냈다. 새 씬을 만드는 요청이면 점프가
없어도 걸린다. v1.11.11이 붙인 접촉 노멀 remedy가 그대로 따라간다.

### 3.3 카메라가 필요한 요청의 빈 템플릿 차단 (결함 A)

먼저 `agent.py` 시스템 프롬프트에 안내를 넣었다 — 빈 템플릿에는 카메라가 없고, 카메라는
primitive가 아니다. **효과가 없었다.** Cam4·Cam5 모두 여전히 `template="empty"`를 보냈다.
사용자 문구("빈 씬")가 시스템 프롬프트의 설명을 이긴다.

그래서 게이트로 옮겼다. 요청이 카메라를 필요로 하는데 `unity_create_scene`이
`template="empty"`로 오면 차단하고, **보내야 할 인자를 그대로 준다.**

```text
Policy blocked unity_create_scene with template="empty": this request needs a camera,
and an empty scene contains no camera and no light, so nothing renders and every
behaviour check is blocked before it runs. Send the same call with template="basic" —
that provides Main Camera and a light. "빈 씬" refers to gameplay objects, which
template="basic" also leaves empty.
```

세 실행 모두 **다음 호출에서 그대로 따랐다.** 이 게이트는 카메라 검사가 요청된 경우에만
켜진다. 카메라가 필요 없는 요청은 빈 템플릿을 그대로 쓴다(테스트로 고정).

`agent.py`의 안내도 남겨뒀다. 게이트가 막는 것은 씬 생성 한 곳뿐이고, 카메라를 Cube
primitive로 만드는 실수(Cam4에서 실제로 나왔다)는 안내만 잡는다.


## 6. 남은 과제

1. **또 다른 요청 형태.** 이번에 확인된 것은 "형태가 바뀌면 결함이 나온다"는 사실 자체다.
   레벨 데이터(LevelLoader), 다수 오브젝트 절차 생성, 부스트/대시는 아직 측정된 적이 없고,
   같은 방식으로 새 결함이 나올 것으로 봐야 한다.
2. 결함 C는 다른 곳에도 있을 수 있다. 콘솔을 읽는 지점이 여기 하나인지 확인하지 않았다.
3. 카메라 게이트는 `unity_create_scene` 한 지점만 본다. 기존 씬을 열어 카메라가 없는
   경우는 검증 계층만 잡는다.
4. Rigidbody 회전 고정, 점프 상한 10.0의 저중력 씬 오탐은 v1.11.11에서 그대로 남았다.
5. 브리지 도메인 리로드·held-key 재큐잉의 Unity 통합 회귀 테스트.
