# v1.11.26 — 모르는 인자를 버리고 성공을 돌려주고 있었다

A0의 관통 표본을 찾다가 그 아래 있던 원인을 만났다. **도구가 받지 않는 인자를 조용히
버리고 `{"status":"ok"}`를 돌려준다.** 모델은 하지도 않은 일을 했다고 믿는다.

---

## 1. 추적

A0의 남은 장애물은 "관통 표본이 없다"였다. 코인을 플레이어 경로 위에 직접 놓고 재보려고
`A0Seg1` 씬을 열었더니, `Item`이 이미 `(1.5, 1.0, 0.0)` — **플레이어 시작점
`(0, 1, 0)`에서 오른쪽으로 1.5, 같은 높이**에 있었다. 이동 측정이 그 위를 지나간다.

그런데 세 번의 측정 모두 `disappeared: False`였다. 획득 스크립트를 봤다.

```csharp
// Collectible.cs — Item에 붙어 있다
void OnTriggerEnter(Collider other) {
    if (other.CompareTag("Player")) { Destroy(gameObject); }
}
```

```text
Player.tag = "Untagged"
```

**분기가 영원히 거짓이다.** `policy_lint`의 `undefined_compare_tag`가 잡지 못한 이유는
`Player`가 Unity **내장** 태그라 "정의됨"이기 때문이다. 문제는 정의가 아니라 부착이었다.

## 2. 원인 — 인자가 조용히 사라진다

모델은 태그를 설정하려 했고, 로그에 그 호출이 있다.

```text
호출: unity_modify_gameobject {"target": "Player", "tag": "Player"}
응답: {"status":"ok","result":{"path":"Player"}}
```

성공이 돌아왔는데 태그는 붙지 않았다. 그 도구의 스키마를 보면 이유가 나온다.

```text
unity_modify_gameobject 파라미터
  target · name · active · parent · position · rotation · scale
```

**`tag`가 없다.** 모르는 인자가 버려지고 성공이 반환됐다.

이 세션에는 **태그를 설정하는 도구가 아예 없다.** 그러니 모델이 어떻게 시도하든
모든 오브젝트는 `Untagged`로 남고, `CompareTag` 분기는 전부 죽는다.

### 2.1 범위

기록된 실행에서 내장 태그를 `CompareTag`로 비교한 것은 5건이고, 그중 **4건이 이
방식으로 태그를 "설정"했다.**

```text
20260722_161023  Goal.cs · Hazard.cs → CompareTag("Player")   "설정" 함
20260805_114644  Goal.cs            → CompareTag("Player")   "설정" 함
20260805_114747  EnemyDefeat.cs     → CompareTag("Player")   "설정" 함
20260805_121349  Collectible.cs     → CompareTag("Player")   "설정" 함
20260723_123005  PlayerMovement25D  → CompareTag("Respawn")  시도조차 없음
```

**골인 판정·적 처치·아이템 획득이 전부 같은 방식으로 죽어 있었다.** 그리고 호스트는
그것을 볼 검사가 없어(A0) `verified`를 냈다.

## 3. 변경 내용

### 3.1 받지 않는 인자는 거절한다

`UnityTools`는 MCP 세션에서 받은 스키마를 이미 갖고 있다(`self._schemas`). 그것으로
호출 전에 판별해 **브리지에 보내지 않고** 오류를 돌려준다.

```json
{"status": "error",
 "error": "unity_modify_gameobject does not accept tag. Accepted parameters:
           active, name, parent, position, rotation, scale, target.
           The call was NOT executed — nothing changed. There is no tool that
           sets a GameObject tag; identify objects with a marker component and
           GetComponent<T>() instead."}
```

- 실행되지 않았다는 것을 명시한다 — 조용한 성공이 문제였으므로
- 대안을 함께 준다. 태그 도구가 없다는 사실은 모델이 알 수 없다
- 스키마가 아직 없으면(세션 연결 전) 통과시킨다. **모르는 것을 근거로 막지 않는다**

### 3.2 빌더 안내를 양방향으로

기존 안내는 "닿은 대상을 마커 컴포넌트로 식별하라"였는데, 모델이 쓴 코드는 **반대
방향**이었다 — 핸들러가 코인 쪽에 있고 플레이어를 식별한다. 그 경우를 명시했다.

> 핸들러가 코인 쪽에 있어도 상대는 컴포넌트로 식별한다 —
> `other.GetComponent<PlayerMovement>() != null`. **이 세션에는 태그를 설정하는
> 도구가 없으므로** 모든 오브젝트는 `Untagged`로 남고 CompareTag 분기는 영원히
> 거짓이다.

## 4. 검증

### 4.1 단위 테스트

**276 → 279건**, subtest 48건. 전부 통과.

- 받지 않는 인자가 오류가 되고 **브리지 호출이 일어나지 않음**
- 정상 인자는 그대로 통과
- 스키마가 없을 때는 막지 않음

### 4.2 실측

§1~2가 라이브 씬과 실행 로그에서 직접 확인한 것이다. `A0Seg1`의
`Player.tag == "Untagged"`, `Collectible.cs`의 `CompareTag("Player")`,
그리고 `{"status":"ok"}`를 돌려준 `tag` 인자 호출.

### 4.3 측정하지 않은 것

- **새 거절이 라이브에서 모델을 어떻게 바꾸는지 보지 않았다.** 모델이 안내대로
  컴포넌트 식별로 넘어가는지, 아니면 다른 우회를 시도하는지는 다음 실행에서 나온다
- **다른 도구에도 같은 공백이 있는지 전수 확인하지 않았다.** 이 수정은 모든 도구에
  일괄 적용되지만, 실제로 모델이 자주 틀리는 인자 이름은 아직 `tag` 하나만 관측됐다
- A0의 관통 표본은 **여전히 없다.** `Item`이 경로 위에 있었는데도 거리가 0.773~1.21로
  기록된 이유는 아직 설명되지 않았다 — 다음 사이클의 재료다
