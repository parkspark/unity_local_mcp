# v1.11.28 — 사라진 것을 Play Mode 정지가 되돌리고 있었다

v1.11.27이 접촉 거리의 단위를 고치고 표본을 모으러 나갔더니, 아이템이 **깊게 겹쳤는데
6회 연속 `disappeared: false`**였다. 빌더를 의심했지만 배선은 멀쩡했다. 결함은 측정
쪽에 있었다 — **구간마다 Play Mode를 정지하는데, 정지는 런타임 `Destroy()`를
되돌린다.**

---

## 1. 추적

같은 프롬프트(아이템 획득 형태)를 6회 돌렸다. 표면 간격은 의도대로 나왔다.

```text
상호작용 대상  −1.000  −0.999  −0.948  −0.942  −0.926  −0.255
```

**전부 겹쳤고, 전부 `disappeared: false`였다.** 첫 용의자는 A4(트리거 배선)였지만
씬 파일이 반증했다 — 5개 씬 모두 `m_IsTrigger: 1`이 정확히 하나씩 있었다. 트리거가
맞고, 플레이어가 관통했고, 그런데 안 사라진다.

측정 순서를 봤다.

```text
contact_before 샘플
  d 구간   → restart_play() → 관통, Destroy 발생
  a 구간   → restart_play() → 씬 리셋, 아이템 부활   ← 증거가 여기서 지워진다
  점프     → restart_play() → 또 리셋
contact_after 샘플                                    ← 아이템이 다시 있다
```

`measure_motion()`은 구간마다 `restart_play()`로 시작하고, 그 안의
`unity_play_mode {"action":"stop"}`이 씬을 직렬화 상태로 되돌린다. 그런데
`contact_after`는 **모든 측정이 끝난 뒤 한 번만** 찍혔다.

**`disappeared`는 사실상 마지막 구간에서만 관측 가능했다.** 기록 전체에서
`disappeared: true`가 하나뿐이었던 것이 그 증거다 — 그 하나(`Coin_2`, y=4)는
**점프로 닿았고, 점프가 마지막 구간이다.** A0이 "사라진 표본이 없다"고 적어 온 것은
빌더가 못 만들어서가 아니라 호스트가 지우고 있었기 때문이다.

## 2. 변경 내용

### 2.1 정지 직전에 훑는다

```python
async def restart_play() -> bool:
    if contract.playing:
        if contract.contact_before:
            await sample_objects(contract.contact_after)   # ← 정지 전
        await self._verification_call(contract, "unity_play_mode", {"action": "stop"})
```

### 2.2 사라진 표본은 덮어쓰지 않는다

매 구간 샘플을 그냥 덮어쓰면 다음 구간의 "부활한 상태"가 이긴다. 판별을
`contact_already_gone()`으로 뽑아 `verification.py`에 두고 양쪽에서 쓴다.

```python
def contact_already_gone(sample):
    if not sample:
        return False
    return bool(sample.get("missing")) or sample.get("active") is False
```

`disappeared`의 의미가 "지금 없다"에서 **"측정 중 한 번이라도 사라졌다"**로 바뀐다.
Play Mode가 여러 번 재시작되는 이상 이쪽이 맞는 정의다.

## 3. 검증

### 3.1 첫 양성 표본 — 라이브

수정 이전의 6회는 임계값 재료로 쓸 수 없다(측정이 지우고 있었다). 그래서 **배선이
정상이고 아이템이 정지해 있던 씬**을 `--repair-existing`으로 재검증했다.

```text
075623  대상 gap=−1.0    disappeared=True    [verified]   ← 이동 구간에서 잡힌 첫 양성
075510  대상 gap=−0.89   disappeared=False   [failed]
```

**이동 구간의 소멸이 처음으로 영수증에 남았다.** 그리고 실패한 쪽이 그 옆의 결함을
드러냈다(§3.2).

### 3.2 곁들여 나온 빌더 결함 — 트리거 + Rigidbody = 무한 낙하

`disappeared=False`로 남은 두 실행의 아이템 Y를 훑었다.

```text
r8 원본     y: 1.00 → 0.86 → −9.03 → −44.63
r5 재검증   y: 1.28 → 1.24 → −13.87 → −53.55
```

**트리거 콜라이더는 바닥과 충돌하지 않는다.** 거기에 non-kinematic Rigidbody를 붙이면
아이템이 월드 밖으로 떨어진다. 플레이어가 도착했을 때 그 자리에 아무것도 없다.

| 씬 | Item 구성 | 결과 |
|---|---|---|
| r4 | Script + SphereCollider(trigger), **Rigidbody 없음** | 획득됨 |
| r5 | Script + SphereCollider(trigger) + **Rigidbody** | 낙하, 획득 불가 |

r4는 원래 Rigidbody가 붙어 낙하했고 **repair가 그것을 떼어 통과했다.** r5는 같은
repair가 실패했다. 즉 이 결함은 실재하고, 현재 repair는 절반만 고친다.
[STATUS A5](STATUS.md)로 남긴다.

### 3.3 A4 표본이 하나 늘었다

새 실행 하나(`A1ItemPickup_r7`)가 트리거를 아예 만들지 않았다(`m_IsTrigger: 1` 0개).
A4는 재생 6건 + 라이브 2건이 됐다.

### 3.4 단위 테스트

**286 → 287건**, subtest 48건. 전부 통과. `contact_already_gone()`의 네 경우
(missing / 비활성 / 정상 / 표본 없음)와, "활성 여부를 아직 못 읽은 표본은 사라진 것이
아니다"를 고정했다.

### 3.5 측정하지 않은 것

- **임계값 재료는 사실상 리셋됐다.** 수정 이후 표본은 2건(양성 1, 음성 1)뿐이다.
  이전 6건은 측정이 지운 값이라 분포에 넣을 수 없다
- **`surface_gap`은 접촉 여부의 단위이지 구조물/대상을 가르지 않는다.** 구조물 쪽이
  −0.5~+0.5로 상호작용 대상의 구간과 겹친다. 가르는 것은 `scripts` 필드다
- **접촉 후보의 좌표는 시작 시점에 한 번만 찍는다.** §3.2처럼 오브젝트가 움직이면
  간격이 허수가 된다. r8의 −0.534는 이미 y=−46에 있던 물체를 y=1로 놓고 잰 값이다.
  **아직 고치지 않았다** — 낙하 자체가 결함이라 그쪽이 먼저다
- 판정은 여전히 바꾸지 않았다. `contact_candidates`는 기록이다
