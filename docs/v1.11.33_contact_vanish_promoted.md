# v1.11.33 — A0을 기록에서 판정으로

v1.11.23부터 여섯 사이클 동안 `contact_candidates`는 **기록만** 했다. 판정을 붙이려면
임계값이 필요했고, 임계값을 고르려면 뒤집히는 지점이 필요했다. v1.11.32가 마지막
방해물(구르는 플레이어)을 치웠고, 여기서 경계를 고정해 승격한다.

---

## 1. 경계는 0이다

회전을 잠근(`constraints = 112`) 같은 씬에서 **아이템 높이만** 바꿨다. 전부 `verified`,
repair 0회, `player_max_tilt = 0.0`.

| 아이템 y | 표면 간격 | `disappeared` | 영수증 |
|---|---|---|---|
| 3.10 | **+0.100** | False | 101251 |
| 2.95 | **−0.050** | **True** | 101401 |
| 2.80 | **−0.198** | **True** | v1.11.32 §2 |

0을 가운데 두고 양쪽이 채워졌다. v1.11.31이 본 "−0.35 ~ −0.50"은 구르는 플레이어가
만든 허수였음이 이걸로 확정된다.

## 2. `contact_target_did_not_react`

**발동 조건을 좁게 잡았다.** 넓히는 것은 언제든 할 수 있지만 오탐은 되돌리기 어렵다.

| 조건 | 이유 |
|---|---|
| 요청이 "닿으면 사라진다" 형태 | 밟기 제외 — 호스트 입력은 좌우 이동과 제자리 점프뿐이라 위에서 밟는 접촉을 못 만든다. 클리어·체력 제외 — 소멸이 옳은 신호가 아니다 |
| 간격 < **−0.25** | 경계는 0이지만 한참 안쪽만 판정한다. 실측 −0.199는 정상이었다 |
| `player_max_tilt ≤ 15°` | 기운 캡슐은 세로 반폭이 절반이 되고 호스트는 겹침을 과장한다(v1.11.32) |
| 대상에 사용자 스크립트가 붙어 있음 | 바닥은 늘 겹친다(간격 −1.0). 이것이 유일한 방벽이다 |
| 측정 후 상태가 "사라지지 않음" | v1.11.28의 sticky 표본을 쓴다 |

기운 실행은 **`measured_checks`에도 넣지 않는다.** 측정 못 한 것을 측정했다고 적으면
v1.11.2가 막은 공집합 성공이 다른 이름으로 돌아온다.

## 3. 검증

### 3.1 라이브 — 검출 → repair → 측정

트리거는 켜 두고 **아이템의 콜라이더를 껐다**(관통은 되되 반응만 죽은 상태).

```text
102330  시도1: ['contact_target_did_not_react:Pickup']
        시도2: []      →  gap −1.0, disappeared=True
        measured_checks에 contact_vanish 포함, player_max_tilt=0.0
```

**A0이 처음으로 판정을 냈고, repair가 고쳤고, 재검증에서 소멸이 측정됐다.**

### 3.2 실패한 주입 둘 — 배운 것

양성 사례를 만드는 데 두 번 실패했고, 둘 다 정보를 남겼다.

1. **트리거를 끄면 아이템이 벽이 된다.** 플레이어가 관통하지 못해 간격이 −0.25
   안쪽으로 안 들어가고, A0은 발동하지 않는다. 그 경우는
   `trigger_handler_without_trigger_collider`가 잡는다 — **두 검사가 겹치지 않고
   각자의 결함을 본다**(영수증 101834)
2. **비활성 MonoBehaviour도 `OnTriggerEnter`를 받았다.** `Pickup` 컴포넌트를
   `enabled = false`로 저장했고 씬 파일에 `m_Enabled: 0`이 남았는데 아이템은
   그대로 파괴됐다(영수증 102011). 플레이어 쪽에 중복 핸들러는 없었다
   (`PlayerMovement.cs`에 `OnTriggerEnter` 없음). **"비활성 컴포넌트는 트리거
   콜백을 안 받는다"는 가정이 틀렸다**

### 3.3 단위 테스트

**299 → 309건**, subtest 48건. 전부 통과. 요청 형태 게이트(밟기·클리어 제외), 경계
바깥 무판정, 기운 실행 무판정, 기울기 미상 무판정, 구조물 제외, 소멸한 것 무판정,
그리고 실패가 자기 검사 이름과 repair 안내까지 닿는 것을 고정한다.

### 3.4 측정하지 않은 것 — 이 검사의 약한 곳

**오탐 근거가 얇다.** v1.11.29의 낙하 검사가 189건 재생으로 얻은 것 같은 계수가 없다.

```text
접촉 후보가 있는 영수증        : 31
기울기 때문에 판정 보류        : 29   ← player_max_tilt가 v1.11.32의 새 필드
새 검사가 실패로 만들었을 것   :  0
```

**0은 "오탐 없음"의 증거가 아니다.** 31건 중 29건은 기울기 필드가 없어 건너뛴 것이고
실제로 판정된 것은 2건뿐이다. 판정 범위를 좁게 잡은 이유가 이것이다.

그 밖에 —

- **대상에 스크립트가 없으면 못 본다.** 핸들러가 플레이어 쪽에만 있는 형태가
  기록상 6건 중 4건이었다. 스크립트 조건을 빼면 바닥·발판이 전부 실패로 떨어져
  지금은 안전하게 넓힐 방법이 없다
- **경계가 씬마다 같은지 모른다.** 스윕은 한 씬에서만 돌렸다
- 접촉 후보의 좌표는 여전히 시작 시점 한 번만 찍는다
